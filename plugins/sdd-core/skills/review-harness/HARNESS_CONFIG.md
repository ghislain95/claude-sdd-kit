# `.sdd/harness.yaml` — review harness configuration

One file per project, versioned, generated by `sdd-init` and edited by hand afterwards. Everything
under `.sdd/` is gate machinery (dev-factory, `change-risk-classification`): a pull request that
changes it opens the irreversible gate and is merged by the owner, never by an agent.

## Schema

```yaml
budget:
  minutes: 90            # wall-clock limit for the whole run on one change
  agent_runs: 30         # every dispatched agent and every forked skill counts (SKILL.md §6)
  effort: high           # highest agent effort the harness uses: medium | high
  heavy_builds: 1        # heavy builds (full suite, mutation, bundle) running at once
  bug_hunt_level: medium # level given to /code-review: low | medium | high
  rounds: 3              # fix rounds before escalating to the owner

angles:                  # conditional angles only; a missing key = the default globs below; [] = off;
                         # keys for always-on angles are ignored
  security:    ["**/auth/**", "**/*.sql", "**/migration/**", "**/*Controller*", "package*.json", "pom.xml"]
  performance: ["src/main/**", "src/features/**"]
  interface:   ["**/*.tsx", "**/*.css", "**/i18n/**"]

mechanical:              # omit a key when the tooling is absent
  conventions:           # list of commands; each non-zero exit is a finding
    - "./mvnw -q test -Dtest=ArchitectureTest"
    - "npm run lint"
  tests:                 # map
    run: "npm test"      # the changed modules' test command
    mutation: null       # command with {files}, e.g. "npx stryker run --mutate {files}"; null = absent
  security:              # list of commands
    - "npm audit --omit=dev --audit-level=high"
  performance:           # list of measured budgets
    - name: "main bundle"
      command: "npm run build && du -k dist/assets/index-*.js"
      threshold: "500 kB"
  interface: []          # list of commands (accessibility linter, component or snapshot tests)
```

- `{files}` is replaced with the changed files the command applies to: those under the path the
  command works on (for a multi-module project, the module's folder).
- `budget.agent_runs` should cover at least the selected angles + one fork per forking angle (`bugs`
  forks `code-review`, `security` forks `security-review`) + 1 verifier for the first pass, plus
  `rounds` × (1 developer + the re-run angles + their forks + 1 verifier). `sdd-init` writes 30, enough for three
  rounds on a typical change.
- `effort` uses the agent effort vocabulary; `bug_hunt_level` uses `/code-review`'s levels. They are
  independent: a `high` effort agent may run `/code-review` at `medium`.

## Defaults when the file is missing

The budget above, the `angles` globs of the schema example as default globs (they also apply to an
angle whose key is missing from a present file), no mechanical command. The always-on angles still
run (spec-conformance, conventions, bugs, tests, sourced-claims). The report says which defaults were
used.
