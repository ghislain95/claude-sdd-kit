# Review angle — project conventions and architecture

The project's `code-reviewer` agent (generated by `sdd-init` from the project's own rules) is the
reviewer for this angle: it carries the module checklists, the forbidden dependencies and the
"hidden quality drop" search. Your job is to run it with mechanical backing and to report in the
shared format (`../review-harness/FINDINGS.md`).

## Method

1. Dispatch the `code-reviewer` agent on the diff (`git diff <base>...HEAD` plus uncommitted changes),
   telling it the change id and asking for the `Fails when` part on every BLOCKER and MAJOR.
2. Run the mechanical checks listed under `mechanical.conventions` in `.sdd/harness.yaml`
   (architecture tests, import or layer lint, formatter in check mode). A failing check is a finding
   of its own, at the line the tool reports.
3. If the project has no `code-reviewer` agent, review yourself against `CLAUDE.md`, `AGENTS.md`, the
   module docs (`CODING_RULES.md`) and the ADRs, using the same checklist headings.
4. Re-tag the agent's findings in the shared format; keep its severities unless a finding has no
   scenario (then MINOR, per `FINDINGS.md`).

## Never

- Accept an exemption added to make a rule pass (an ignore list, a narrowed rule, a suppression
  comment) as a fix: it is a 🛑 BLOCKER unless `design.md` justifies it.
